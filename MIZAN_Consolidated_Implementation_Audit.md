## 3. Critical Defects and Risks

1. **Release Signing Missing (`:app:bundleRelease` Failure):** `signingConfigs.release` expects `KEYSTORE_PATH` (defaulting to `/app/applet/my-upload-key.jks`), `STORE_PASSWORD`, and `KEY_PASSWORD`. None exist, causing `:app:signReleaseBundle` to fail.
2. **R8 / Shrinking Disabled in Release (`app/build.gradle.kts:46–48`):** `buildTypes.release` sets `isMinifyEnabled = false` and `isCrunchPngs = false`. Although `app/proguard-rules.pro` is authored, R8 optimization/obfuscation has not been enabled or tested against Hilt, Room, Kotlinx Serialization routes/vault DTOs, or `AndroidKeyStore`.
3. **Seeded Domain Category Feeds Are Empty (`MISSING_OR_EMPTY`):** `DataModule` binds `DisabledRemoteDatasetUpdater` and `NoTrustedKeySignatureVerifier`, and there is no `WorkManager` worker or UI dataset import/update flow. Selecting **Social Media** or **Adult Content** in commitment setup activates zero category domains on its own unless custom domains are entered.
4. **No `POST_NOTIFICATIONS` Permission on Android 13+:** `AndroidManifest.xml` omits `POST_NOTIFICATIONS`. On API 33+, `DomainFilterVpnService` foreground notification visibility (including its "Stop" notification action) can be suppressed by the OS without user-granted notification permission.
5. **Cross-Reboot Wall-Clock Gap in 24-Hour Removal Request (`RemovalRequestStateMachine.kt:77–90`):** Forward clock manipulation is only caught within the same `bootSessionToken`. If a user reboots and advances the system wall clock past `unlocksAt`, `monotonicValid` is `false` and the request becomes `READY_TO_EXECUTE` (inherent offline limitation unless monotonic uptime across reboots or external trust exists, which should remain clearly disclosed).
6. **Background VPN Restart Restrictions on Reboot/Update (`BootAndUpdateRecoveryReceiver.kt:92–98`):** On Android 14+/15+ and restrictive OEMs, starting a `specialUse` foreground `VpnService` from `BOOT_COMPLETED` or `MY_PACKAGE_REPLACED` may be blocked by OS background-launch restrictions; code catches this and surfaces an error prompting manual app open, leaving DNS filtering inactive until reopened.
7. **IPv4-Only DNS Forwarding & Private DNS Bypass (`UnderlyingDnsResolver.kt:55`):** `UnderlyingDnsResolver` filters `linkProps.dnsServers.filterIsInstance<Inet4Address>()` and `DomainFilterVpnService` adds only IPv4 TUN/route (`10.120.0.1/32`, `10.120.0.2/32`). IPv6-only networks, Android Private DNS (DoT), browser DoH, or another active VPN bypass local domain filtering (partially disclosed via `VpnHealthMonitor` Private DNS / conflict flags, but requires real network validation).
8. **Unignored `debug.keystore.base64` & Missing `.git`:** `.gitignore` ignores `debug.keystore` and `*.keystore`, but not `debug.keystore.base64` present at workspace root.
9. **Deprecated API Warning (`UsageStatsHealth.kt:75`):** `appOps.unsafeCheckOpNoThrow(...)` produces a Kotlin compilation deprecation warning in both debug and release builds.
10. **Placeholder `ENTER_DISCIPLINE_MODE` Choice (`CommitmentCompletionViewModel.kt:219–226`):** Selecting "Enter Discipline Mode" only persists `CompletionNextStep.ENTER_DISCIPLINE_MODE` and shows a pending-specification note; no post-detox discipline workflow or ongoing rule set exists.

## 7. Release Readiness Verdict

**Verdict: `NOT READY — BLOCKERS REMAIN`**

Although the core architecture, Milestones 0–5 flows, custom DNS packet codec, and PIN/24h-removal hardening pass all 162 JVM/Robolectric unit tests, release readiness is blocked by:
1. Missing release signing configuration (`my-upload-key.jks` / signing credentials absent, failing `:app:bundleRelease` at `:app:signReleaseBundle`).
2. `isMinifyEnabled = false` in `buildTypes.release` (R8 shrinking/obfuscation never enabled or verified).
3. Incomplete Milestone 6 category feed pipeline (`DisabledRemoteDatasetUpdater`, `NoTrustedKeySignatureVerifier`, no `WorkManager`, empty seeded category datasets, no `POST_NOTIFICATIONS` declaration for API 33+).
4. Unimplemented `ENTER_DISCIPLINE_MODE` post-detox behavior and template-only `androidTest` coverage.
5. Zero physical-device, live-network VPN, OEM AccessibilityService, or `AndroidKeyStore` hardware verification.
